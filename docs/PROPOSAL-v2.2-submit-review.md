# 评估提案 v2.2 — 补“提交 / 审稿”环节（草案，未实施）

> 更正（2026-11-24）：这一版理解错了方向。它把“提交”理解成了“提交审稿”，其实用户说的是“用户提交目录、大纲、章节等数据供稿，AI 按用户的思路创作”。正确的评估见同目录的 `PROPOSAL-v2.2-user-driven.md`。这一版里关于审稿包、批准记录的部分仍可作下游补充，但不是本次要改的主线。

日期：2026-11-24。触发：《时间啊，你慢些走》第 1–2 章实测。结论：要改，做瘦补丁 v2.2，不重写技能。

## 一、你的判断是对的，缺口是真实的

SKILL.md 只写了“作者批准”和“CHAPTER_COMMIT”，但文件技能这条路（Muse 在聊天里走的这条路）上没有提交、没有审稿件、没有批准记录、没有提交脚本。

- 有的：3 个检查脚本（check_chapter / check_hooks / check_continuity）、两份人工清单、合同模板、正文模板。
- 没有的：`drafts/` 草稿区、`reviews/` 审稿区、提交脚本、审稿包模板、批准记录、回滚脚本、统一跑分脚本。
- 对照：同一仓库的 MCP / Studio 那条路已经有这些——`drafts/NNN.md`（草稿不成正史）、`auditChapter`（先在临时副本上干跑）、`commitChapter`（审计不过拒绝提交，须作者批准）、`rollbackChapter`（回滚并清理登记的人物和伏笔）。两条路已经分叉，文件技能这条路落后了。

所以第 1、2 章我是手工提交的：手改 `progress.md` / `summary.md` / `character_state.md` 三个文件，没有 diff 预览，没有审稿文件。你点“继续写第 2 章”，我默认当成了对第 1 章的批准，但这个批准没有落到任何文件里。以后想查“第 1 章是谁、什么时候、按什么意见通过的”，查不到。审计输出也只在终端里闪过，没有存档。

## 二、实测踩到的坑（第 1–2 章，都有证据）

1. 字数靠猜。第 1 章 1078 → 1734 → 2103 → 2269 字，扩了 3 次；第 2 章 1240 → 1637 → 1901 → 2024 → 2150 字，扩了 4 次。模板只给了一个 2100–3000 的区间，没有按 must_happen 分段的字数预算，写完才知道不够。
2. 格式是暗坑，不是明规则。伏笔台账我第一版写成表格，`check_continuity.py` 直接报 9 个 FAIL；`knows.md` 里的人名必须和 `bible/characters.md` 的 `##` 标题一字不差，我写了“陆时安（核心主角）”就对不上；`progress.md` 里必须有 `committed: 1` 这样的行，SKILL.md 和模板里都没写，只在样例书里能翻到；标题写“第一章”会报 warning，脚本只认“第1章”。
3. 合同和正文重复抄写。合同在 `outline/chapters/NNN.md` 的代码块里，正文在 `chapters/NNN.md` 的 frontmatter 里，两份字段一模一样，全靠手工抄，没有脚本校验它们是否一致。钩子交接（规则 11）也只靠人工看，脚本从不检查上一章的钩子在下一章合同里有没有交代。
4. 没有版本。草稿改一次就覆盖一次，v1 改错了找不回来；回滚只有文字描述，没有 Python 脚本，和 MCP 的 `rollbackChapter` 不对等。

核心规则本身没问题：文件即真相、钩子 + 欲望阻断、knows 清单、伏笔台账、只改错段，这些在实测里都立住了。不用动它们。

## 三、改什么：分三级，只做瘦补丁

### P0 — 必须补：提交 / 审稿闭环（新 Step 3.5）

1. 新增目录 `drafts/`（草稿不成正史）和 `reviews/`（每章一份审稿包）。
2. 新增 `scripts/submit_chapter.py`：校验合同 → 草稿，先做字数预检，生成审稿包，不碰正史。
3. 新增审稿包模板 `templates/review_packet.md`，每章一份 `reviews/NNN.md`，固定包含：正文、三个脚本的输出原文（存档，不是终端闪过）、8 维人工审计逐条引用原文、提交后 state 将要变什么（summary /  ledger / knows 的 diff 预览）、作者决定栏（通过 / 改 X 处 / 打回）+ 日期。
4. 新增 `scripts/commit_chapter.py`：只有带“通过”的审稿包才能提交；提交前先干跑三脚本，不过就拒绝；提交是原子的（正文 + state 一起进，或都不进），并写入 `state/approvals.md` 批准记录。
5. 新增 `scripts/rollback_chapter.py`：Python 版对齐 MCP 的 rollbackChapter，修已提交章先回滚其事实和新登记人物。
6. 新增 `scripts/check_all.py`：一键跑三个脚本，输出存到审稿包里，退出码即结论。

### P1 — 消灭格式脆性

7. 人物 ID：`bible/characters.md` 每人加一个短 ID（如 `lu-shian`），合同、knows、state 都用 ID 引用，脚本按 ID 匹配，不再按 `## 标题` 全文比对。
8. 标题二选一并统一：要么脚本接受“第一章 / 第1章 / Chapter 1”三种，要么模板强制只用“第1章”。两边改一边，不能继续一面说一种、一面认一种。
9. 补齐缺的模板：`templates/knows.md`、`templates/progress.md`（含 `committed: N` 格式）、`templates/character_state.md`，并加 `scripts/validate_book.py`：Gate 2 前先校验书架子齐不齐，缺文件就拦住，不等到提交时才 FAIL。
10. 新增 `scripts/check_contract.py`：校验合同与正文 frontmatter 字段一致，并校验上一章钩子在下一章合同里是否交代（规则 11 机器化）。

### P2 — 写作效率

11. 字数预算：合同里每个 must_happen 节拍给一个字数预算（如每节 300–400 字），提交前先算预算，写不够在动笔前就知道，不用写完扩 4 次。
12. 草稿版本化：`drafts/NNN-v1.md`、`NNN-v2.md`，只改错段时保留上一版，审计历史跟版本走。
13. Python 与 MCP 对齐：审计规则以一份为准，避免 TS 的 `auditEngine.ts` 和 Python 三脚本将来各改各的。

## 四、不做的事

- 不重写 SKILL.md 的核心规则，不动 8 欲望、不动伏笔生命周期、不动盲写和 Gate 3。
- 不把 MCP / Studio 的整套东西搬进文件技能，只搬提交 / 审稿 / 回滚这三个动作。
- 不加新体裁、不加新平台。v2.2 只补流程缺口。

## 五、实施顺序（建议）

先做 P0（提交 / 审稿 / 回滚 / 统一跑分），跑通《时间啊，你慢些走》第 3 章当首测；P0 稳了再做 P1；P2 看 P0、P1 的实测反馈再定。改完先在 `examples/sample-book/` 上跑回归，三脚本必须全过，CHANGELOG 记一笔，再推 GitHub。
